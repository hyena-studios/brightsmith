### Added

- **OSI semantic-model export (`docs/specs/osi-semantic-model-export.md`).** New `python -m brightsmith.infra.osi generate` composes the governance artifacts the pipeline already produces — data contracts (datasets, fields, grain→primary-key), the business glossary (field descriptions + `ai_context.synonyms`), Mermaid ER data models (relationships, join columns resolved from PK/grain — unresolvable ones skipped loudly, never invented), `governance/domain-context.md` (model-level AI instructions), and optional `DomainHints.metrics` — into a single [Open Semantic Interchange](https://github.com/open-semantic-interchange/OSI) v1.0 YAML document at `governance/semantic-model.osi.yaml`, making gold-zone data products consumable by any OSI-aware platform (Snowflake, Tableau, dbt, Databricks, …). CDE/PII flags and contract identity travel in `brightsmith` `custom_extensions`. The export is deterministic (no timestamps, sorted collections), so `... osi check` is a real drift gate (exit 1 on a stale or hand-edited file); missing optional artifacts leave sections empty, malformed artifacts or zero gold contracts raise `OSIExportError` (loud-failure doctrine). `BaseMCPServer` serves the document as a new `brightsmith://semantic-model` resource when present, and a new `get_semantic_model` framework tool lets the model fetch it mid-conversation (resources are client-pulled and not universally auto-attached) — unscoped for the full document, or scoped to one table for just that dataset, its relationships, and the model's metrics. The OSI file is an export boundary only — contracts/glossary/models remain the internal sources of truth. Tests: `tests/infra/test_osi.py` (composer, enrichment, relationship resolution, determinism, drift, loud failures, CLI), `tests/mcp/test_base_mcp_server.py` (resource present/absent).
- **W1/H3 — `pipeline_gate.py` and `run.py` characterization test coverage raised from 25%/61% to 97%/99%.** `tests/infra/test_pipeline_gate_validation.py` and `tests/infra/test_run_coverage.py` exercise `validate`, `_validate_zone_specific`, `_validate_warehouse_population`, `check_zone_transition`, `status_summary`, `audit_report`, every `_cmd_*` CLI handler, and `run.py`'s manifest-shape parsing, preflight-relocation, DQ/contract/golden-dataset helpers, headless-readiness diagnostics, run history, and CLI — in-process (hand-built state / mocks) so pytest-cov can see them, complementing the existing subprocess-based cross-process tests in `test_pipeline_gate.py`/`test_pipeline_runner.py`. No production bugs surfaced by this pass — both modules' documented behavior matched their tests on the first write.
- **W2/Theme 1 — consumer-journey smoke test, run entirely outside the checkout.** `scripts/consumer_journey_smoke.sh` builds the wheel, installs it into a scratch venv outside this repo, scaffolds a project via `python -m brightsmith.setup init`, verifies the scaffold (DQ templates present + non-empty, `data/bronze/iceberg_warehouse` exists), drops in a fixture domain pack (`tests/fixtures/consumer/`: a stub `BaseIngestor` over inline data + `manifest.yaml`/source YAML), runs `python -m brightsmith.run --zone bronze`, and queries the result through `BaseMCPServer.query_iceberg`/`query_iceberg_simple` — asserting real rows come back, not `SELECT 1` test theater. Wired into CI as a new blocking `consumer-journey` job (single lane, Python 3.12; `.github/workflows/ci.yml`).
- **W3a-d/M1/M6 — the read path stopped materializing whole tables.** `iceberg_setup.read_with_duckdb` gained `columns=`/`limit=` parameters (pushed into PyIceberg's `scan(selected_fields=..., limit=...)`, pruning at the scan layer rather than in Python); `BaseIngestor._build_existing_grains` now reads only the dedup-grain columns instead of every column of every row; `BaseMCPServer` replaced its per-call "rebuild the DuckDB world" pattern with a persistent, lazily-opened query connection (`_ensure_query_connection`) that caches `iceberg_scan` views and refreshes only when table locations actually change (closing M6 — tables no longer re-register on every query); `query_iceberg_simple` pushes filters/columns/`LIMIT` into the SQL itself (parameterized values, `_IDENT_RE`-validated identifiers) so a small `limit` never materializes more than DuckDB needs to scan. Upstreamed from futureproof-data's own `_query_engine.py` workaround, closing the loop the audit's Theme 1 called for.
- **W3e/M1 — `contract.verify_contract` no longer materializes whole tables either.** The two checks that were fully solvable without any row-level read now are: `grain_unique` runs a single SQL aggregate (`COUNT(*) - COUNT(DISTINCT (grain_cols...))`) over a column-pruned Arrow scan of just the grain columns (`_count_duplicate_grains`); `row_count` reads the table's `total-records` figure straight from Iceberg snapshot metadata (`_table_row_count`) — zero data-file reads at any table size. `freshness` and `required_columns` (which genuinely need row-level values — latest timestamp, per-row nulls) keep a bounded, column-pruned read capped at `_BOUNDED_READ_LIMIT` (100k rows) instead of the old unlimited full-table read. New tests: a table with duplicate grain rows FAILs `grain_unique` via the aggregate path; `row_count` reflects the real snapshot-tracked count and FAILs once a tightened threshold exceeds it (`tests/infra/test_contract.py`).
- **Governance database maintenance section (M5/L5, README.md).** Documents the governance-DB's actual growth characteristics (one Iceberg snapshot + one small Parquet file per event, append-only, full-table-scan reads), a worked `table.maintenance.expire_snapshots().older_than(...)` example (verified against the pinned PyIceberg version), a note that in-engine compaction isn't yet exposed at this PyIceberg version, rough thresholds for when to care (low tens of thousands of events / multi-month projects), and a retention note for `governance/run-history/` (documentation only — no rotation code ships, matching the audit's explicit "defer implementation" call).
- **Drift guard: packaged DQ rule templates must match the canonical copy byte-for-byte.** `tests/infra/test_dq_rule_templates_drift.py` fails loudly the moment `src/brightsmith/_templates/dq-rule-templates/*.json` (the wheel-packaged copy, H4a) diverges from `governance/dq-rule-templates/*.json` (the human-edited canonical copy) — same filenames, same bytes, on both sides.

### Fixed

- **C1 — `BaseMCPServer.query_iceberg` can now actually read real Iceberg tables.** `enable_external_access=false` was applied before any `iceberg_scan` view was ever queried; since views are lazy, every real-table query failed with `Table … does not exist`, masked by tests that only ran `SELECT 1`. Fixed by scoping `allowed_directories` to the resolved warehouse root *before* disabling external access (verified against the pinned DuckDB 1.5.0 — it honors `allowed_directories` even with `enable_external_access=false`), then `SET lock_configuration=true` before the untrusted statement executes so it cannot flip either setting back. `read_csv('/etc/hosts')` and a direct `SET enable_external_access=true` remain blocked.
- **M2 — headless pipeline runs no longer execute every DQ rule once per zone.** `run.py`'s `_run_dq_for_zone` called `dq_runner.run_rules()` unfiltered and discarded non-matching results after the fact, so a 4-zone run executed every rule 4× and wrote 4 governance `dq_runs` records for the same rules. `run_rules()` gained an optional `rule_filter: Callable[[dict], bool] | None` parameter, applied before execution (not after); `_run_dq_for_zone` now passes `rule_filter=lambda r: _rule_matches_zone(r, zone)`, reusing the existing zone-matching logic. Each rule now executes exactly once per pipeline run, at the point its own zone runs — bronze P0 failures still abort before silver/gold/mcp run at all (fail-fast unchanged), and each zone's governance write reflects only that zone's rules. New test spies on `execute_sql_rule` across a real multi-zone `run_pipeline()` and asserts every rule id appears exactly once (`tests/infra/test_run_coverage.py`).
- **M8 — the SessionStart hook no longer silently pip-installs into whatever Python is active.** The inline `pip show brightsmith > /dev/null 2>&1 || pip install -e ${CLAUDE_PLUGIN_ROOT}` command was environment-blind (no uv/venv detection) and swallowed every install failure. Replaced with `hooks/ensure-installed.sh`: checks importability directly against the active Python, prefers `uv pip install -e` when uv is on PATH *and* a venv is active (else falls back to the active Python's own `pip` module — never a bare `pip` that might resolve to a different interpreter), and on any failure — including PEP 668 "externally-managed-environment" errors — prints one instructive message naming the exact manual command and a venv hint, always exiting 0 (a hook must never brick the session). Happy path (already installed) is silent; a successful auto-install prints one short line. Tested via subprocess invocation against a stubbed `PATH` (`tests/hooks/test_ensure_installed.py`) — no existing shell-hook test convention existed in this repo to follow.
- **H2 — domain transform failures were misclassified as `SKIPPED` (exit 0).** `run.py`'s `_execute_zone_module` raised bare `ValueError` for "no module registered", and `run_pipeline` caught `ValueError` to detect that case — which also caught any `ValueError` a domain transform itself raised (e.g. `append_data`'s strict-mode column error), silently downgrading a real failure to `SKIPPED`. A dedicated `ZoneNotRegisteredError` is now raised for the "not registered" case; a transform's own `ValueError` now correctly yields `FAILED` / `EXIT_TRANSFORM_ERROR`.
- **H1 — the `mcp:` manifest section is now real.** `DomainManifest` had no `mcp` field and `load_manifest` never parsed one, so `serve.py`'s domain-server path was unreachable — consumers silently got the generic `BaseMCPServer`. Added `DomainManifest.mcp`, parsed from the manifest's top-level `mcp:` block; `serve.py` now tries that block first, then a `pipeline.zones.mcp` entry (the shape field manifests use), then falls back to the base server — logging which server was selected and why at every step, and warning only on genuine load failures (not merely "shape unused").
- **H4a — DQ rule templates now ship inside the installed package.** `setup._copy_dq_templates` resolved templates via a repo-root escape (`_TEMPLATES_DIR.parent.parent.parent / governance/dq-rule-templates`) that only exists in a source checkout; a pip-installed wheel silently got zero templates. The five JSON templates now also live at `src/brightsmith/_templates/dq-rule-templates/` (packaged; the `governance/` copy remains the human-edited source of truth — both locations cross-reference each other), and the copy now fails loudly (`FileNotFoundError`) if the packaged templates are missing or empty instead of silently no-op'ing.
- **H4b — scaffolded warehouse path corrected.** `setup.py` scaffolded `data/raw/iceberg_warehouse`; `config.py`'s default is `data/bronze/iceberg_warehouse`. Fixed to match, so scaffolded projects no longer get an empty decoy directory.
- **H4c — `setup.py`'s module docstring is now truthful** about what `init()` actually generates (directories, `pyproject.toml`, `.gitignore`, DQ templates) — it previously promised a `CLAUDE.md`, ingestor skeleton, and first spec that were never written.
- **H5.1 — multi-table sources (`tables:`) no longer crash the manifest loader.** `domain_loader._load_source_config` hard-required singular `table:` (`KeyError` otherwise). Now accepts `tables:` as either a YAML list or a mapping keyed by table name (the shape multi-table sources like O*NET naturally use) via a new `SourceConfig.tables: list[str]` field; `table`/`full_table_name` remain populated (first entry) for back-compat.
- **H5.2 — the nested `pipeline.zones` manifest shape is now parsed.** `run.py`'s zone registry previously understood only the flat `pipeline: {zone: {module, function}}` shape; a manifest using the nested `pipeline: {zones: {zone: [steps, ...]}}` shape (what multi-source domains produce naturally — file-path modules, ordered per-zone step lists) silently left the registry empty with no error. The registry now supports an ordered list of steps per zone, loadable from either shape (file-path modules resolved via `importlib.util.spec_from_file_location` against `PROJECT_ROOT`); `_execute_zone_module` executes all steps for a zone in order and aggregates `rows_promoted`/`rows_skipped`. A `pipeline:` block matching neither shape now raises `PipelineManifestShapeError` instead of leaving the registry silently empty.
- **M4/T6a — `dq_runner`'s table-reference regex now matches table names containing digits** (e.g. `gold.revenue_2024`); the previous `[a-z_]+` pattern couldn't match a digit at all, so the view was never registered and the rule errored.
- **L1 — `lineage.py`'s `cmd_history` no longer builds SQL via f-string interpolation** (`WHERE job_name = '{job_name}'`); parameterized (`$1`) to match `governance/queries.py`'s style. Fixes a crash on a `job_name` containing a quote.

### Changed

- **BREAKING — M3: DQ rules with no `status` field no longer default to `active`.** `dq_runner.load_rules()` previously called `rule.setdefault("status", "active")`, so any rules file that simply omitted `status` bypassed the documented `PROPOSED → APPROVED → ACTIVE` lifecycle entirely and executed immediately. The default is now `"proposed"`, matching a freshly-authored rule. Behavior at execution time (`run_rules()`'s new `_gate_rule_lifecycle`): `approved`/`active` rules always execute; `proposed` rules (including status-less ones) execute only when `REQUIRE_HUMAN_APPROVAL` is `False` — an execution-time-only auto-advance per CLAUDE.md's documented toggle semantics, which does **not** rewrite the rules file (a durable transition still goes through `approve_rules`/the `approve` CLI); when `REQUIRE_HUMAN_APPROVAL` is `True`, skipped rules produce one loud `logger.warning` naming every skipped `rule_id` plus the exact `python -m brightsmith.infra.dq_runner approve <ids>` command. **Migration:** any existing rules file that relies on the old implicit-active default must either add `"status": "active"` to each rule, or run `python -m brightsmith.infra.dq_runner approve <rule_id>...` to advance them through the lifecycle explicitly. New tests in `tests/infra/test_dq_runner.py::TestRuleLifecycleGate` cover the default, both approval-toggle branches, the on-disk-file-is-unchanged guarantee, the warning content, and that `active` rules are unaffected by the toggle.
- **L2 — README project-structure section corrected**: removed the stale reference to the already-removed `.claude/agents/` directory (agents live in `agents/`, 25 definitions) and fixed a second stale "setup.md only" claim about the same directory.
- **All repo references aligned to the canonical `hyena-studios/brightsmith`.** Investigation showed the two apparent repos are ONE repo: it lives under the `hyena-studios` org and `jcernauske/brightsmith` is a permanent transfer redirect (left over from a temporary move for hackathon judging). The README install line, the `setup.py`-scaffolded dependency, and `agents/setup.md`'s scaffolding instructions previously used the redirect URL — which would silently break if a new repo ever claimed the `jcernauske/brightsmith` name. All now use the org URL directly (CI badge unchanged — it already pointed at the org).
- **L3 — removed a dead no-op loop in `domain_loader._load_source_config`** (a verbatim dict copy under a misleading "normalize entity key types" comment); replaced with a direct assignment and a truthful comment.

### Internal

- **L4 — repo hygiene**: `.pytest_cache/` and `.ruff_cache/` added to `.gitignore`; the accidentally-committed local dev skill `.claude/skills/webapp-testing/` removed from the working tree.
- New regression/characterization tests for all of the above: `tests/mcp/test_base_mcp_server.py` (C1 — real-table read + post-fix security invariants), `tests/infra/test_pipeline_runner.py` (H2), `tests/mcp/test_serve.py` (H1), `tests/infra/test_setup.py` (H4), `tests/infra/test_domain_loader.py` (H5.1, `tests/fixtures/domain_loader/onet_source_trimmed.yaml`), `tests/infra/test_pipeline_manifest_shapes.py` (H5.2, `tests/fixtures/run/nested_pipeline_manifest.yaml`), `tests/infra/test_dq_runner.py` (T6a), `tests/infra/test_lineage_roundtrip.py` (L1).
- New regression/characterization tests for the second Round-2 batch (M1/M2/M3/M5/M6/M8, L5): `tests/infra/test_contract.py` (W3e — grain-uniqueness/row-count via the SQL-aggregate path), `tests/infra/test_run_coverage.py` (W4 — real multi-zone `run_pipeline()` with a spy on `execute_sql_rule` proving one execution per rule), `tests/infra/test_dq_runner.py::TestRuleLifecycleGate` (W5), `tests/hooks/test_ensure_installed.py` (W6 — new `tests/hooks/` directory), `tests/infra/test_dq_rule_templates_drift.py` (W7b).

## [0.4.0] — 2026-07-02

### Fixed

- **A1 — direct `config.PROJECT_ROOT = …` assignment now recomputes derived paths**, matching `configure()`. Previously, assigning a primary input (project_root/name/approval/floor) through the back-compat shim replaced only that one field and left `WAREHOUSE_PATH` / `DQ_RULES_DIR` / `CATALOG_PATH` / … pointing at the *old* root — an internally-inconsistent snapshot. Assigning a *derived* path (e.g. `config.DQ_RULES_DIR = tmp`) remains a single-field override.
- **`lineage verify` and `lineage generate-docs` were crashing** — both read `con.description` after `con.sql(...)`, which is `None` in DuckDB 1.5 (only `con.execute()` populates it), raising `TypeError: 'NoneType' object is not iterable`. These CLI paths were untested (25% module coverage); now fixed to read the DuckDB relation's own `.columns`, and covered by new round-trip tests.
- **Glossary sync was not idempotent** — the `glossary_terms` grain keyed on the `now()`-stamped `updated_at`, so re-running `sync_from_files` re-appended every term (unbounded governance-DB growth) despite its "idempotent via promote()" contract. The grain is now content-based (`term_id` + the term's content fields): an unchanged re-sync is a no-op, while a genuine edit still creates a new row.
- **`BaseMCPServer.query_iceberg` no longer crashes or leaks on a bad query** — execution errors from untrusted SQL are returned as a structured `[{"error": …}]` (matching the allowlist-rejection shape) inside a `try/finally` that always closes the connection. Previously an invalid statement raised out of the tool handler and skipped `con.close()`, leaking a connection on every failure on the long-lived stdio server.
- **DuckDB / SQLite connection leaks eliminated** — every `duckdb.connect()` is now context-managed, and PyIceberg `SqlCatalog` engines are cached per (warehouse, catalog, project) instead of rebuilt per call. A full test run went from **542 `ResourceWarning: unclosed database` to 0**.

### Changed

- **Module-level config shim + `GRIST_*` vars: removal deferred, shim hardened.** 0.3.0 targeted these for removal in 0.4.0; instead the shim's assignment asymmetry (A1, above) was fixed and the shim retained for compatibility. Full removal in favour of `get_config()` / `configure()` is deferred to a future major release. `GRIST_*` continue to emit a `DeprecationWarning`.
- **`verification run` gate is now conditional on golden-dataset presence** — a golden dataset present → it is enforced (mismatch / pass-rate below `--threshold` = hard FAIL); a golden dataset absent → `SKIPPED` (exit 0, printed loudly), since verification is not applicable. A dataset that exists but yields no checkable values is still a FAIL.
- **`glossary_terms` grain changed** from `["term_id", "updated_at"]` to content-identity fields (see Fixed). Existing rows re-derive on the next sync; the table is write-only backfill, so no reader is affected.

### Added

- **`brightsmith.infra.iceberg_setup.reset_catalog_cache()`** — drops the process-wide `SqlCatalog` cache (disposing engines); called automatically by `configure()` and by the test fixture between cases.
- **Characterization + regression test suites** — `test_lineage_roundtrip.py` (emit→read→query→CLI), `test_governance_sync_migration.py` (sync/migration end-to-end + idempotency), `test_no_unclosed_connections.py` (asserts no `unclosed database` ResourceWarning escapes a read/query flow), and `test_verification.py` (gate semantics). Two production bugs above were surfaced by these.
- **No-swallowed-exceptions guard now scans the entire `src` tree** (was a hand-maintained 8-file list). Every broad `except Exception` in the package must re-raise, narrow to a specific type, or carry a written allowlist justification — a new module with an unjustified swallow fails CI automatically.

### Internal

- **Plugin manifest + `pyproject.toml` version bumped `0.3.0 → 0.4.0`.**

### Governance-hardening batch (also in 0.4.0)

_The pre-remediation "Unreleased" work — loud-failure gates, sessions table, typed CI — also ships in 0.4.0._

#### Changed

- **BREAKING — `log_agent_finding` now raises on a governance-DB write failure by default** (was fault-tolerant: logged a warning and returned `None`). The governance DB is authoritative for the agent-activity feed, so a dropped finding must fail the calling pipeline step rather than silently disappear — the same loud-failure doctrine the DQ and contract gates follow. Pass `strict=False` to restore best-effort logging where a logging hiccup must not fail the surrounding work. `write_agent_activity` (the underlying writer) already raised and is unchanged.
- **Pipeline-gate completion is now gated on the governance-DB write.** `complete_step` / `skip_step` commit the authoritative JSON state file *last* — only after `_emit_governance_event` (and any `--finding` write) succeeds. Previously the file was saved *before* the Iceberg write, so a failed governance write left the step marked `COMPLETED` on disk and the next `check` cleared anyway. Now a failed governance write leaves the file un-advanced, so the next step's `check` stays `BLOCKED` and the pipeline stops deterministically — no agent cooperation required. Retrying `complete` is idempotent (governance writes dedup on their grain `record_id`).

#### Added

- **`pipeline_gate complete --finding "<summary>"`** — records an end-of-step summary to the governance `agent_activity` feed atomically with completion. The finding write is strict: if it fails, completion is not recorded and the next `check` stays `BLOCKED`.
- **Session logs restored as an Iceberg-authoritative `sessions` governance table** (the deleted `docs/sessions/` practice). New `sessions` schema, `write_session()` / `log_session()` writers (strict-by-default, idempotent on `session_id`), and `get_sessions()` query. The markdown file under `docs/sessions/` becomes an optional human-readable export; the table is the record of truth. `docs/workflows/session-logging.md` updated accordingly.

#### Internal

- **Agent definitions consolidated to a single source of truth (`agents/`).** The repo previously carried two copies of all 25 agents — the plugin-shipped `agents/` and a project-local `.claude/agents/` — which had drifted 1,087 lines apart. Because pipeline skills dispatch via the `bs:` plugin namespace (which resolves from `agents/`), the shipped copy was the stale one: it lacked the governance-DB logging blocks and the `temporal-modeler` / `lineage-tracker` / `mcp-engineer` rewrites. The maintained `.claude/agents/` content was promoted into `agents/` and the project-local copy was removed. Dogfood in-repo via `claude --plugin-dir .` so agents resolve as `bs:*`, exactly as an installed user sees them.
- **Plugin manifest version bumped `0.2.0 → 0.3.0`** to match `pyproject.toml`.
- **Ruff ruleset expanded** to `E, F, B, I, UP, SIM` (was default `E/F` only). `E501` and a few opinionated `SIM`/`UP042` rules are ignored with documented reasons; 173 findings auto-fixed (import sorting, `datetime.UTC`, explicit `zip(strict=...)`), the rest fixed by hand. CI now enforces the expanded set.
- **No-swallowed-exceptions guard extended** to full-scope coverage of `governance/queries.py`, `infra/lineage.py`, and `infra/cab.py`. The `cab.py` blast-radius file-parse loops were narrowed to specific exception types; observability/CLI handlers are allowlisted with written justifications.
- **CI: coverage reporting** (`pytest --cov`), a **blocking `pyright` type-check gate** (`pyrightconfig.json`, basic mode over `src`), and a `paths-ignore` filter so docs/agent/skill-only commits don't spend Actions minutes.
- **`pyright` driven to zero errors and gated in CI.** Cut 164 → 25 false positives by declaring the dynamically-served `config` legacy names under `TYPE_CHECKING`; then fixed the remaining 25 real issues — an `_env` overload, None-guards (`relocate` avro schema, `domain_loader` cache_dir fallback, `chaos_monkey` corruption-fn guard), a `Callable` (was builtin `callable`) misannotation, a walrus narrowing in `contract`, `evaluate_threshold(raw_result: Any)`, sentinel `cast`s in `glossary_loader`, and justified `# type: ignore`s for two upstream stub gaps (`pyiceberg` `Table.identifier`, `mcp` `AnyUrl` handler typing). No runtime behavior change — verified by the full suite.
- **Removed committed framework self-development artifacts** (`governance/reviews/`, `audit-trail/`, `runtime-artifacts/`, a stray `pipeline-state` file, a test scorecard) and gitignored those runtime governance dirs. Only `governance/dq-rule-templates/` (shipped content) remains tracked.
- **Decomposed the two governance god-functions.** `sync_from_files` (384 lines) and `migrate_files_to_iceberg` (258 lines) are now thin orchestrators over one `_sync_*` / `_migrate_*` helper per source artifact type (largest helper ~85 lines). Behavior, return-dict keys, and ordering are unchanged — verified by the existing sync/migration tests. Adding a new source is now a helper + one line in the orchestrator tuple.

## [0.3.0] — 2026-06-30

### Fixed

- **Pipeline gate state was silently discarded across processes** (was a critical regression from the Iceberg-authoritative migration — `_save()` had been turned into a no-op while `_load()` still read the JSON file; every `check` after a `complete` reported BLOCKED). Restored dual-write: file is now authoritative for reads in this release; Iceberg event emission is preserved. The three-process repro (`init → complete → check`) now unblocks correctly.
- **Headless runner DQ gate never executed a rule** — `_run_dq_for_zone` replaced all rule execution with `# Simplified: count rules as passed`, meaning the P0 gate could never fail. It now calls `dq_runner.run_rules()` against real Iceberg data, honours the `ZONE_ALIASES` table so both canonical (`bronze`) and legacy (`raw`) table prefixes match, and propagates failures with exit code `EXIT_DQ_FAILURE`.
- **Contract `generate` → `verify` split-brain** — `save_contract` wrote to Iceberg only; `verify` / `list` read from files; the result was "No contracts found" out of the box. Both paths now dual-write YAML files under `governance/data-contracts/`, making round-trips work without running the exporter.
- **Errored P0 DQ rules were excused from blocking** — `validate_after_write` filtered out errored rules before evaluating P0 failures, so a rule that raised an exception was treated as a pass. Errored P0 rules are now included in `p0_failures` and block the gate. The `acknowledge` CLI remains the documented escape hatch.
- **`dq_runner` CLI subcommands `results` / `scorecard` / `badge` required `--spec`** — `get_latest_results(spec=None)` now aggregates the latest run per spec, so all three no-flag forms produce output and exit 0.
- **`_verify_contracts_for_zone` skipped alias-namespaced contracts** — contracts whose table names used legacy zone prefixes (`raw.`, `base.`, `consumable.`, `ai_ready.`) were not matched. The lookup now resolves both canonical and alias names.

### Changed

- **BREAKING — `compute_grain_id` raises `ValueError` on a missing grain field** (was silently hashing the empty string `""`). A missing field now raises immediately with the field name. `None` values are allowed and hash as `"None"`.
- **BREAKING — `compute_grain_id` escapes the `|` delimiter** — grain values containing a literal `|` are now escaped as `\|` before joining, so `("a|b", "c")` and `("a", "b|c")` produce different record IDs. **Any row whose grain values contained `|` will have a different `record_id` in 0.3.0.** Re-run the affected pipeline zones to regenerate record IDs; duplicate detection will reactivate correctly on the first re-promote.
- **`append_data` is now strict by default** — passing a column key that does not exist in the target schema raises `ValueError`. Pass `strict=False` to opt out (legacy behaviour).
- **Config is now accessed via `get_config()` / call-time** — `configure()` now takes effect even after `dq_runner`, `lineage`, `iceberg_setup`, and related modules have been imported. The six import-time bindings that previously froze config at import have been converted to call-time access.

### Added

- **`python -m brightsmith.infra.relocate`** — detects and repairs absolute warehouse paths baked into Iceberg metadata. Flags: `--check` (read-only scan, exits non-zero if any stale prefixes found), `--apply` (rewrites all four metadata layers — SQLite catalog rows, `*.metadata.json`, manifest-list `.avro`, manifest `.avro` — atomically per file, idempotent), `--relative` (rewrites to repo-root-relative paths for warehouses committed to git).
- **`WarehouseRelocationError`** — reading from a warehouse whose baked prefix differs from the current project root now raises this error with the exact `relocate --apply` command printed; silent empty-result reads are no longer possible.
- **`fastavro` dependency** (>=1.9) — required for the `relocate` module's Avro codec-preserving rewrites.
- **GitHub Actions CI** — `.github/workflows/ci.yml` runs `ruff check src tests` and `pytest tests/` on Python 3.11 and 3.12 on every push and pull request; also runs `relocate --check` to guard any committed example warehouses.
- **Characterization test suite for the pipeline gate** — `tests/infra/test_pipeline_gate.py` (≥ 12 subprocess-level tests) encoding the correct cross-process state-machine behaviour.
- **Contract round-trip test suite** — `tests/infra/test_contract_roundtrip.py` covering `generate → list → load → verify` in an isolated tmp project root.
- **No-swallowed-exceptions guard test** — `tests/infra/test_no_swallowed_exceptions.py` parses the enforcement-path modules with `ast` and fails on any bare `except Exception` handler that neither re-raises nor returns an explicit error sentinel.
- **`brightsmith.config.get_config()`** — returns a frozen dataclass snapshot of the current configuration; replaces direct module-level global access in all infrastructure modules.

### Security

- **`BaseMCPServer.query_iceberg` is now read-only** — the DuckDB connection sets `enable_external_access=false` immediately after loading the Iceberg extension; the statement is validated against an allowlist (first keyword must be in `{SELECT, WITH, DESCRIBE, SHOW}`; `COPY`, `INSTALL`, `LOAD`, `ATTACH`, DDL, and DML are rejected before execution). A rejected statement returns a structured error dict. This closes the prompt-injection file-exfiltration path (`COPY (SELECT ...) TO '/path'`). DQ rule SQL from governance JSON (trusted-operator input) continues to run through the separate `dq_runner` path, which is not subject to this allowlist.

### Deprecated

- **`GRIST_*` environment variables** (`GRIST_SERVER`, `GRIST_API_KEY`, `GRIST_DOC_ID`) — now emit a `DeprecationWarning` at first read. Targeted for removal in 0.4.0.
- **Module-level config globals** (e.g., `brightsmith.config.PROJECT_ROOT`) — deprecated in favour of `brightsmith.config.get_config()`. The module-level names remain as thin property aliases for 0.3.x compatibility and will be removed in 0.4.0.

### Internal

- **`governance/product.py` (2,637 lines) split** into `schemas.py`, `writers.py`, `queries.py`, `sync.py`, and `cli.py` under `src/brightsmith/infra/governance/`. `product.py` is retained as a re-export façade so every existing import keeps working. No behaviour change.
